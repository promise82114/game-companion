# Game Companion — 漸進式收斂 Roadmap UX

## 1. 設計目標

將現有 Roadmap 從「需要頻繁展開、收合的攻略文件」，改善為「隨著遊玩進度自然收斂的連續式攻略」。

核心概念：

**未完成的內容完整呈現，已完成的內容自動精簡。**

使用者可以從頭到尾順暢閱讀攻略，也可以在實際遊玩時逐步勾選完成，讓已完成的資訊自然縮小，減少畫面負擔。

不需要額外切換閱讀模式或遊玩模式。

## 2. 核心互動規則

### 2.1 未完成步驟

- 預設完整顯示攻略內容。
- 包含操作說明、重要提醒、獎盃與相關資訊。
- 允許提前閱讀後續所有內容。
- 不強制依序完成，可自由勾選。
- 不應為了閱讀而反覆操作 Accordion。

### 2.2 已完成步驟

- 勾選完成後，自動收斂成精簡摘要。
- 保留步驟名稱、完成狀態及必要識別資訊。
- 可以臨時展開查看完整內容。
- 臨時展開不影響完成狀態。
- 取消完成後，恢復完整顯示。

### 2.3 連續閱讀體驗

- 章節、段落、步驟應形成自然連續的閱讀流程。
- 章節主要作為內容分組與導航標記，不應成為閱讀障礙。
- 已完成內容逐漸縮小，後續未完成內容自然接續。
- 不應強迫使用者切換頁面或模式。
- 勾選完成後避免突然跳動、失去閱讀位置。
- 不自動強制捲動至下一步。

## 3. 章節與段落導航

保留完整攻略的快速定位能力。

建議支援：

- 章節目錄與段落快速跳轉。
- 章節完成數量與進度。
- 一鍵返回目前遊玩進度。
- 自由查看已完成與未完成內容。
- 桌面與手機皆能方便操作。

「目前閱讀位置」與「實際完成進度」應分開處理。

使用者跳到後面閱讀，不代表前面已完成。

## 4. 重要 UX 原則

### 減少操作負擔

使用者應專注於攻略本身，而不是管理介面。

### 漸進式資訊收斂

隨著完成進度增加，已不需要反覆閱讀的內容自然縮小。

### 保留自由探索

使用者可以提前閱讀、回頭查詢、跳轉章節，不應被限制在單一步驟。

### 避免資訊遺失

已完成內容只是視覺精簡，不應刪除攻略資料或重要警告。

### 保持操作連續性

勾選、收斂、跳轉時，應盡量維持使用者的視覺位置與操作脈絡。

## 5. 需要特別考慮的情境

1. 第一次進入，所有步驟都未完成：能否像完整攻略一樣順暢閱讀？
2. 逐步完成：頁面是否自然變短，而不需要手動收合？
3. 回頭查看已完成步驟：能否快速展開，又不影響進度？
4. 跳到後面章節：能否快速定位並返回原本進度？
5. 跨章節完成：能否自然接續下一章？
6. 重新整理或跨裝置同步：完成狀態與畫面是否正確恢復？
7. 有可錯過獎盃或重要警告：是否仍能在必要時機明顯提醒？
8. 攻略很長、完成大量步驟後：是否仍能維持良好的效能與操作體驗？

## 6. 現有系統相容性

優先沿用既有：

- Roadmap 資料結構。
- 步驟完成狀態。
- 獎盃追蹤。
- 本機儲存與 Google Drive 同步。
- 搜尋與篩選。
- 章節及步驟識別方式。

避免為了 UI 改版破壞既有進度資料。

## 7. Codex 執行要求

請先調查目前 Game Companion 的 Roadmap 實作。

特別確認：

- 章節與步驟如何組成。
- Accordion 展開與收合邏輯。
- 完成狀態如何保存。
- 搜尋、篩選、跳轉與定位如何運作。
- 哪些遊戲共用 Roadmap 元件。
- 哪些改動可能影響其他遊戲。

先提出：

1. 現況與主要 UX 問題。
2. 漸進式收斂的建議實作方式。
3. 需要調整的元件與資料。
4. 對現有功能的影響及風險。
5. 最小改版方案與驗收方式。

**第一階段僅調查、規劃與提出建議，不直接修改程式碼。**

## 8. 驗收標準

- [ ] 全新進度時，所有未完成攻略均可連續閱讀。
- [ ] 勾選完成後，對應步驟自動精簡。
- [ ] 取消完成後，恢復完整內容。
- [ ] 已完成步驟可臨時查看詳情。
- [ ] 不需要切換閱讀／遊玩模式。
- [ ] 不需要反覆展開章節才能閱讀後續內容。
- [ ] 支援章節與段落快速定位。
- [ ] 可以一鍵回到目前遊玩進度。
- [ ] 勾選後不會出現明顯的捲動跳動。
- [ ] 不影響原本的進度保存、獎盃追蹤與同步。
- [ ] 手機與桌面皆能順暢操作。
