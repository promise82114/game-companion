# Grounded｜Game Companion 遊戲頁面需求規格 v0.1

> 狀態：待 Codex 盤點與實作。遊戲資料、獎盃條件與地圖座標不得以推測填入。

## 1. 目標與範圍

在既有 Game Companion 專案新增 `/games/grounded/`，沿用既有路由、元件、主題、部署、進度儲存與資料匯入匯出機制。不要另建專案或破壞 Talos 2、Mycopunk 頁面。

- 遊戲：Grounded（非 Grounded 2）
- 平台：PlayStation；以使用者提供的本體 46 項獎盃清單為唯一初始核對基準。
- 初始進度：0/46；不可推測已取得獎盃。
- 目標：完整體驗 Roadmap、可選白金 Roadmap、收集品清單、獎盃對照、原創簡化互動地圖、多人 Shared World 進度展示。
- 不包含 DLC；如來源資料有版本差異，需標記版本、查證狀態與來源。
- 使用繁體中文介面；官方英文獎盃名維持原文。

## 2. 開工前盤點（P0，必做）

1. 盤點現有 `/games/talos2/` 與 `/games/mycopunk/` 的路由、UI、資料 schema、狀態儲存、GitHub Pages base path、測試及部署方式。
2. 優先重用既有 Game Companion 共用模組；禁止為 Grounded 複製整套儲存與同步邏輯。
3. 列出可重用／需新增／需修改的檔案與模組，以及不相容風險。
4. 查證 Grounded 現行版本、PS4/PS5 獎盃清單、Super Win 100% 條件、NG+ 重置／繼承規則及收集品數量。對來源衝突的資訊標為 `unverified`，不要硬編。
5. 輸出 `GROUNDED_P0_REPORT.md`，然後在同一工作流程繼續完成可安全實作的 MVP，不必每個小步驟都等待人工核准；涉及既有資料遷移或刪除時才停下確認。

## 3. 頁面資訊架構

頂部摘要：世界名稱、目前周目、故事階段、獎盃數、Super Win 必要條件進度、最後更新時間。

分頁：

1. **總覽**：今日建議、下一個主線目標、近期不可逆警示、收集完成率、共同遊玩規則。
2. **Roadmap**：依區域／實驗室／Boss／結局分階段；每個步驟可勾選，含前置條件、建議裝備、預估耗時、獎盃關聯、劇透、錯過警示。
3. **收集清單**：乳牙、巨型乳牙、SCA.B、資料文件、錄音、特殊配方、地標、Creature Cards、MIX.R、BURG.L 相關進度等；僅在有可靠證據時標為白金必要。
4. **地圖**：原創示意 SVG 地圖、區域切換、收集品標記、篩選、搜尋、定位、勾選、詳情、清單與地圖雙向連動。
5. **獎盃**：46 項獎盃、分類、達成條件、關聯 Roadmap 與收集品、取得狀態、可補救性。
6. **NG+**：REMIX.R 啟動前驗收、周目切換、繼承／重置規則、NG+ 專屬內容；第一輪與各 NG+ 的隨機乳牙狀態分離。
7. **世界／成員**：Shared World 說明、共同進度與個人進度的區別；MVP 只做本機成員標籤及匯出，不宣稱即時多人同步。

## 4. Roadmap 規則

- 預設「完整體驗」，另可切換「白金目標」。
- 警示類型：`critical` 🔴 不可逆／易錯過、`branch` 🟠 分歧／備份、`prep` 🟡 提前準備、`recommended` 🔵 推薦體驗、`later` ⚪ 可延後。
- 每項步驟包含：id、標題、區域、階段、操作、前置條件、關聯獎盃、關聯收集品、警示、來源、查證狀態。
- Roadmap 至少區分：Oak Lab 起步 → Hedge/Pond/Haze/Black Anthill 實驗室 → Upper Yard/Undershed → Wendell/Mant → Director Schmector 與隱藏 Boss → JavaMatic/結局 → 100% 查漏（可選）→ REMIX.R/NG+（可選）。
- 不得把推薦順序當成唯一合法順序；明確標出可平行探索的區域。
- 保留玩家自訂備註、完成時間、完成者（選填）。

## 5. 收集資料模型

每筆收集品至少：

```ts
interface GroundedCollectible {
  id: string;
  category: string;
  officialName: string;
  zhName?: string;
  regionId?: string;
  locationDescription?: string;
  mapPoint?: { x: number; y: number; layer?: string };
  worldScope: 'base' | 'ngplus' | 'both';
  spawnRule: 'fixed' | 'candidate-random' | 'unknown';
  requiredFor: string[]; // trophy IDs or 'super-win'; only verified links
  sourceUrls: string[];
  verification: 'verified' | 'conflicting' | 'unverified';
}
```

- **定義資料**與**玩家進度**分開儲存；進度以穩定 id 關聯，不因排序或翻譯改變。
- 支援「已取得／未取得／待確認」；不可把未知視為已完成。
- 具備分類、區域、白金必要、未取得、查證狀態篩選，以及名稱搜尋。
- 每個類別顯示已確認的 `完成數／總數`；來源尚未完整時顯示「資料庫未齊」，不可顯示誤導性 100%。
- Super Win 條件與一般獎盃條件分開建模，避免誤判。
- Creature Cards 不得將 Gold Cards 誤列為必要條件（仍須查證版本）。
- NG+ 隨機乳牙以候選位置表示，不可把所有候選點當作單一世界的必收數量。

## 6. 原創簡化互動地圖

### 版權與資料原則

- 不抓取、下載、描摹、向量化、重製或直接使用其他網站的底圖、截圖、圖示、圖磚與受保護的視覺素材。
- **改畫線圖不自動免除著作權風險**；只能使用自行創作的概念性區域示意與合法取得、可核實授權的地理資料。
- 可使用已查證的事實性位置資訊作為獨立資料來源，但應保留來源與授權說明；不得違反來源網站條款或大量自動抓取。
- 不確定的座標不可編造。優先標記「區域已知、精確位置待查證」。

### MVP 地圖功能

- 用 SVG 自行繪製簡化庭院輪廓、池塘、橡樹、樹籬、霧區、沙盒、野餐桌、Upper Yard 等概念性區域；以示意圖為定位基礎，**不是精確導航地圖**。
- 具有縮放、平移、圖層切換（地表／地下／水下／高處）、標記聚合、篩選、搜尋、標記詳情、完成狀態與清單連動。
- 標記點位與底圖分離為 JSON/TS 資料，未來可逐步補足精度。
- 使用者可新增個人自訂標記與備註，且不混入官方收集品資料。
- 地圖需在桌機與手機可用；圖示、顏色、文字共同表達狀態，不只靠顏色。
- 地圖標示「示意位置」與「已核實位置」差異；不得宣稱覆蓋全部收集品，除非已核對清單完整性。

## 7. 多人與進度儲存

- 以一個 Shared World 為單位管理共同進度，個人獎盃與個人強化可按玩家分開。
- 世界共同：基地、主線與世界型收集等，實際共享範圍須查證；個人：PSN 獎盃、個人角色強化等。
- MVP：沿用現有本機儲存及匯入／匯出 JSON，支援 worldId、playerId、schemaVersion、updatedAt。
- 如現有 Google Drive 同步已可重用，先盤點後再整合；未完成前不得標示為「即時共享」。
- 日後多人合併需處理同一項目衝突、來源、最後修改時間與誤勾復原；不可單純 last-write-wins 覆蓋整個世界。
- 提供資料備份、還原及版本升級；不得因資料更新清空勾選紀錄。

## 8. 實作階段

### P0：盤點與查證
- 現有架構、來源、獎盃清單、資料風險、地圖方案。

### P1：可用頁面骨架
- `/games/grounded/` 路由、共用樣式、總覽、46 項獎盃、可勾選 Roadmap、本機保存。

### P2：收集清單與獎盃關聯
- 可靠來源匯入、分類／查漏／搜尋、Super Win 條件矩陣、查證狀態。

### P3：原創示意地圖
- SVG 地圖、區域與圖層、點位、清單雙向連動、響應式操作。

### P4：NG+ 與多人世界
- 周目隔離、REMIX.R 警示、個人／共同進度區分、匯入匯出及現有同步能力整合。

### P5：驗收與完善
- 手機與桌機測試、資料完整性、效能、可及性、GitHub Pages 正確部署。

## 9. 驗收條件

- 既有 Talos 2、Mycopunk 頁面正常運作；不改壞共用儲存資料。
- `/games/grounded/` 在 GitHub Pages 子路徑可直接開啟及重新整理。
- 初始 0/46；46 個獎盃名稱與使用者清單一致，不混入 DLC。
- 每個勾選都可保存、重新整理後保留，且可匯出再匯入。
- 收集品與獎盃關聯有可追溯來源；未知資料顯示待查證。
- 地圖為自行創作的簡化示意，不使用第三方底圖或未授權素材。
- 第一輪與 NG+ 不互相污染；隨機候選點不被當成必收。
- 不宣稱具備尚未完成的多人即時同步。
- 提供 `GROUNDED_IMPLEMENTATION_REPORT.md`：完成項目、尚缺資料、風險、測試、下一步。

## 10. Codex 執行原則

先讀取 Repo 現況及本規格，優先完成 P0～P2，再完成 P3 的可用示意地圖。遇到來源不足的項目可保留待查證資料結構與 UI，不得填假座標或假獎盃條件。保持既有設計語言與可擴充架構；不要為單一遊戲引入大型地圖服務或不必要依賴。完成後執行專案現有 build、lint、test（若存在），回報結果。
