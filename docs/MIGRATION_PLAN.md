# 舊進度匯入與回復

來源 repo、舊網址及正式 Drive 備份維持原狀。新站使用新的 namespace；不掃描舊 localStorage、不搬 OAuth Token／Drive file ID／同步 Base，也不把首次匯入當成三方同步。

## 使用者流程

1. 在舊站匯出 JSON，保留這份原始檔；測試期間仍以舊站為正式來源。
2. 新站進入正確遊戲的「備份與還原」，選擇 raw JSON 或該遊戲舊／新 envelope。其他遊戲、錯 Schema 或損壞的已知記錄會拒絕。
3. 新站先在獨立 `import.{uuid}` Key 保存來源與目前進度原文；儲存失敗便停止。這是新增備份紀錄，不寫主進度。
4. 預覽已取得數、未知項目數及逐筆差異，選擇本機／來源，或批次選擇。未知項目不因另一端沒有記錄而被刪除。
5. 下載包含目前進度與 `recoveryBundle` 的 JSON，確認已保存，再套用已選差異或還原。當下仍須成功保存本機快照；預覽後主進度或其他分頁有變更便停止並要求重比。
6. 新存檔包含 `importHistory` 的兩端原文，未知頂層／envelope 欄位或同名欄位碰撞可從該處還原；已知項目以選擇結果顯示。匯入不寫 Drive。

「套用已選差異」可處理來源的取消勾選／空筆記，不只是聯集 true。既有資料未提供的收藏／筆記／設定群組保留；還原模式會對已提供群組的來源缺項設明確 false／空值，並尊重差異中「保留本機」的選擇。需要完全依來源還原時，先批次「全部使用來源」。

## 備份與未知資料

一般匯出仍是相容的進度 raw JSON，雲端面板匯出則有新 projectId envelope。遷移下載的 JSON 也是可匯入的目前進度，另外帶 `recoveryBundle.source` 和 `.current`。若要回到「來源」那一份，可將該物件另存 JSON 後重新走預覽；程式不自動替使用者切換來源。

unknown ID 的原記錄保留在群組內；unknown 頂層、外層 envelope 及碰撞值保存在完整匯入原文，沒有靜默捨棄。既有未識別欄位在 validate／一般匯出及已知 entry 編輯時保留。來源 raw 不代表舊 OAuth 或同步狀態有效，不能作新站 Base。

歷史與原文不自動清除，會增加 localStorage／JSON 體積；目前匯入上限 5 MiB。超限／配額失敗時保留當前進度並停止，不為成功匯入清除任何舊資料。快照最多 12 筆，不取代下載備份。

## 正式切換與回復

本次沒有正式切換。切換前需重新匯出舊站最新資料、比對總數／完成數／筆記／設定／未知項目並保護新站現況，確認後才改正式使用入口。舊 repo 不封存、不轉址。

切回舊站前先匯出新站期間的進度。程式回退不會回退資料；不要假設舊站的舊驗證器會保留新站擴充欄位。舊站相容輸入需獨立轉換、預覽與人工確認，並保留完整新站備份；本次未執行這種逆向寫入。

新站多分頁改為不可變操作日誌；整理 checkpoint 保留欄位版本，先保存後移除已捕獲操作。同步結果 rebase 並以 expected-value 條件套用，保留同步期間編輯；同項同時編輯仍按日誌順序決定，瀏覽器整體儲存交易與跨裝置時鐘不作保證。舊版新站分頁的主 Key 改寫另存 journal.external.archive／pending，需從「比較舊分頁另存的進度」備份預覽後處理；未處理時停止同步。

同步每個遊戲、帳號有獨立 sync.base／sync.pending／sync.recovery。Base 只在遠端確認與本機成功保存後更新；失敗保留 pending，下次先讀取核對 syncRevision。原 OAuth／舊站備份不搬入；新站首次配對必須確認。每次授權以唯一名稱合成檔驗證 If-Match，再開放手動同步；使用者將在正式網域測試，尚未宣稱真實遠端競爭已驗收。
